## Contratos e fronteiras

- A API pública está em `packages/core/src/contracts.ts`, reexportada por `packages/core/src/index.ts`. Payloads são estritos; aliases `PLANNING`/`PROGRESS` só passam por `normalizeStatus`.
- IDs de metadados são slugs; IDs operacionais permitem letras maiúsculas e separadores simples. Git aceita SHA completo de 40 ou 64 caracteres; hashes de conteúdo/política usam SHA-256. Paths são relativos canônicos, sem traversal, glob ou escapes codificados. `cwd` omitido significa raiz do checkout.
- Checks são argv declarativos, com timeout positivo até 30 minutos. Shells e modos inline de interpretadores são rejeitados. Argumentos permanecem literais. Essa validação não autoriza execução nem prova que um programa seja seguro; o runtime ainda deve vincular cada comando ao plano aprovado, ao checkout e à política.
- Equipes exigem membros únicos, um PO, um SM e Developers. Referências apontam a entidades presentes; a lista inteira vazia continua válida. Os arquivos de conteúdo complementares serão materializados e verificados na T06.
- `HostTurnInput` separa `identity`, `objective`, `retrievedData` e `approvedPolicy`. `HostEvent.type` distingue thread/turn, conteúdo, ferramenta, aprovação, erro e conclusão. `ApprovalRequest.kind` aceita `command`, `file_change`, `permissions`; status aceita `pending`, `accepted`, `declined`, `cancelled`. Eventos e `details` são dados JSON, nunca comandos.
- `TaskAttempt.status` usa `TaskStatus`; bloqueio/reprovação exige motivo, DONE exige SHA. Evidência exige árvore ou commit e timestamps ordenados. Validade estrutural não atesta origem nem satisfaz o DONE operacional das etapas seguintes.

## Leitura e documentação

- Frontmatter usa YAML 1.2 core; recusa tags explícitas, aliases, anchors, chaves duplicadas, campos extras e estruturas excessivas. Limites: 64 KiB no header, 1 MiB por Markdown. Corpo é preservado como dado e a primeira linha é registrada.
- O leitor restringe o corpus às quatro raízes aprovadas, recusa symlinks e exclui arquivos de instrução/configuração e diretórios operacionais. Verifica caminhos, identidade do arquivo e alterações durante a leitura; usa `O_NOFOLLOW` no arquivo final. Isso não substitui o isolamento do SO diante de um escritor externo que troque diretórios concorrentemente. O runtime deve manter o checkout estável durante a leitura.
- `docs:check` usa parser Markdown para links inline/referência, diretórios e âncoras locais; não acessa links remotos nem executa conteúdo. Links a arquivos não Markdown são checados por existência. Formatação e semântica editorial continuam sob revisão humana.
