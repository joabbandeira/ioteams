# T11 — Política imutável e isolamento de repositório

Spec: `docs/superpowers/specs/2026-10-14-ioteams-v1-design.md`. Esta é uma parcela da especificação aprovada, não uma nova autoridade operacional.

## Entrega

Criar @ioteams/runtime módulos policy/workspace/git. Validar caminhos resolvidos, symlinks, repo/remote/branch/SHA, clean tree e ausência de escritor; criar checkout/worktree exclusivo da demanda sem reset/force-push. Política humana congelada e hash fora corpus/checkout, scope de arquivos e CheckCommand argv aprovados. Controlar instruções/config do projeto: inventariar arquivos autocarregáveis e exigir confiança explícita, verificar instructionSources retornadas; jamais promover docs/personas a base/developer instructions. Descobrir permissões suportadas e bloquear quando não puder aplicar o perfil necessário. Tests em repos descartáveis com remote bare; scopes/traversal/branch changes/2ºwriter/instruction injection são recusados. Não manipular repositórios reais de terceiros ou config global.

## Critérios de aceite

- Plano aprovado é imutável e paths/comandos/remote são verificados deterministicamente.
- Checkout exclusivo e escritor único são aplicados; corpus e instruções não aprovadas não ampliam autoridade.

## Validação

- `npm run typecheck` → exit 0
- `npm test` → exit 0
- `npm run docs:check` → exit 0

## Conclusão

Revisar mudanças, registrar decisões relevantes, commit coerente e push normal em origin/develop. Confirmar SHA remoto e emitir o recibo do handoff. Não iniciar outra tarefa ou criar sessões filhas.
