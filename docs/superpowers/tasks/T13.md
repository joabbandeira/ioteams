# T13 — Ciclo implementar, validar, corrigir e entregar por Git

Spec: `docs/superpowers/specs/2026-10-14-ioteams-v1-design.md`. Esta é uma parcela da especificação aprovada, não uma nova autoridade operacional.

## Entrega

Implementar coordenador sequencial sobre plano aprovado. Developer aplica tarefa em fresh turn, reviewer independente em outra sessão read-only, host executa checks argv e registra evidência/árvore antes de commit. Falha→REJECTED→TODO com reason/id/history, nova tentativa e contexto mínimo; limites 3 tentativas/30min. Não aceitar teste aprovado em texto do agente; detectar mudança de plano/checks/scopes e validação que modificou árvore. Host faz commit normal apenas de mudanças autorizadas, push para branch/remote fixados e ls-remote exato antes DONE. Persistir intent/result para reconcile após crash; push failure não recompõe commit; recusa/timeout/infra mantém run em estado distinto. Tests com fake Codex + local bare repos: fail/fix/pass, review rejection, out of scope, stalled process, denial, push uncertainty/remote advance e chamadas duplicadas.

## Critérios de aceite

- Ciclo completo gera evidências reais e commit/push no SHA autorizado.
- Falhas voltam à correção; retry/restart/push incerto não duplicam efeitos ou concluem indevidamente.

## Validação

- `npm run typecheck` → exit 0
- `npm test` → exit 0
- `npm run docs:check` → exit 0

## Conclusão

Revisar mudanças, registrar decisões relevantes, commit coerente e push normal em origin/develop. Confirmar SHA remoto e emitir o recibo do handoff. Este é marco de feature; o coordenador dispara e acompanha CI depois da liberação do checkout. Não iniciar outra tarefa ou criar sessões filhas.
