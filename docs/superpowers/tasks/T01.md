## Entrega

Criar workspaces npm e @ioteams/core/@ioteams/catalog com exports src/index.ts. Implementar schemas Zod e tipos dos contratos mínimos da spec; fixtures boas/ruins e tests de validação (campos desconhecidos, paths/SHA/checks inseguros, relações estruturais e índices de linhas). Implementar parser seguro de frontmatter declarativo, sem avaliação de tags/funções, e leitor que não segue symlinks; catálogo vazio inicial é válido, referências entre entidades são verificadas conforme elas passam a existir. `npm run docs:check` verifica links locais e estrutura de entidades presentes; depois T06 há teste explícito de catálogo inicial completo. Contratos de entidade podem ter campos complementares seguros documentados.
Adicionar Vitest, Playwright, TypeScript, tsx, configs e scripts raiz typecheck, test, test:unit, test:integration, test:e2e, docs:check, build e build:demo. `npm test` executa testes unit/integration existentes; comandos de subconjunto com diretório vazio devem informar indisponibilidade, sem fabricar teste aprovado. Adicionar smoke E2E significativo do demo existente (LISA, abrir tarefa, rejeição/replanejamento e critérios DONE). Preparar workflow GitHub Actions somente push tags ci/ioteams-v1-* com npm ci, typecheck, test, docs:check, build e E2E; nenhum segredo/modelo real. Fixar ações por SHA oficial verificado. Migrar lockfile aninhado para lock raiz mantendo instalação em painel compatível com workspaces. Ajustar build painel para saída ignorada por padrão e comando demo explícito, sem modificar HTML demo aprovado. Atualizar README de execução afetado. Instalar dependências/browser apenas no escopo local, com margem de disco (>5 GB); estimativa inicial adicional <2 GB.

## Critérios de aceite

- Instalação npm reproduzível e workspaces TypeScript funcionais.
- Contratos rejeitam entradas inválidas e metadados são lidos sem execução.
- Protótipo preservado e testes de comportamento/smoke passam.
- CI responde somente a tags de marcos e todos os checks locais passam.
